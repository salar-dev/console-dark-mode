# Dark Mode for Play Console & App Store Connect

A Chrome extension (Manifest V3) that gives **Google Play Console** and
**App Store Connect** a carefully crafted dark theme. It is scoped to those two
developer dashboards only and never touches any other website.

**Install:** [Chrome Web Store](https://chromewebstore.google.com/detail/dark-mode-for-play-consol/onhgocpclfamcmeemabpammbldjncaae) · [Website](https://salar-dev.github.io/console-dark-mode/)

| | |
|---|---|
| Sites | `https://play.google.com/console/*` · `https://appstoreconnect.apple.com/*` |
| Permissions | `storage` (to remember your toggles) + host access to the two sites above |
| Data collection | None. Nothing leaves the browser. See the [privacy policy](https://salar-dev.github.io/console-dark-mode/privacy.html) (`docs/privacy.html`). |
| Language | English |

## Features

- One master switch plus an independent switch per site.
- **Follow system theme**: dark only while the OS is in dark mode, switching live.
- Keyboard shortcut `Alt+Shift+D` to toggle (changeable at `chrome://extensions/shortcuts`).
- Toolbar icon dims when the extension is switched off.
- The popup shows each console with its own icon; a whole row is a toggle.
- Images, app icons, charts and status colours keep their original colours
  (saturated colours are never remapped, whether they come from CSS or inline styles).
- Turning it off restores the original page instantly, no reload needed.
- A small "Dark Mode By: Salar Dev" credit link sits in each console's own
  footer (linking to github.com/salar-dev) while the theme is on.

## Development

1. Open `chrome://extensions`, enable **Developer mode**.
2. **Load unpacked** → pick the `extension/` folder.
3. Open Play Console or App Store Connect. Use the toolbar popup to toggle.
4. After editing CSS, click the ↻ reload button on the extension card and refresh the tab.

## Build for the Chrome Web Store

```bash
./scripts/build.sh
```

This validates the manifest, popup files and JavaScript, then writes
`dist/console-dark-mode-v<version>.zip`. Upload that zip in the Developer Dashboard.

Everything the Developer Dashboard asks for (description, single purpose,
permission justifications, privacy answers, which image goes where) is in
[STORE_LISTING.md](STORE_LISTING.md). Store screenshots are produced
with `scripts/store/` from the real consoles, with app names, icons, account
details and numbers replaced by fictional ones before capture.

## Website

`docs/` is a static site (plain HTML/CSS/JS, no build step, no external requests)
published with GitHub Pages: *Settings → Pages → Deploy from a branch → `main` /
`/docs`*. It lives at <https://salar-dev.github.io/console-dark-mode/> and hosts the
privacy policy the store listing links to.

The Chrome Web Store URL lives in the `data-store-url` attribute on `<html>` in
`docs/index.html` and on every "Add to Chrome" button; change it there if the listing moves.
Screenshots are the WebP copies in `docs/assets/` (regenerate from `assets/store/screenshots/`).

## How the theme is built

Both consoles ship hashed or build-specific class names (styled-components on
App Store Connect, Angular `_ngcontent-*` attributes on Play Console), so a
hand-written selector list rots quickly — that is why generic dark-mode
extensions leave white patches and vanishing elements. This extension uses
three layers instead:

1. **The sites' own hidden dark themes.** Play Console carries a complete
   Material dark token set gated on an `.acx-dark-theme` ancestor class;
   App Store Connect's `tb-*` component library has a dark palette under
   `html.dark`, and Apple's shared header/footer web components have `.dark`
   variants inside their shadow roots. The content script switches these on.
2. **A dynamic theming engine** (`src/engine/`). It reads the page's own
   stylesheets through the CSSOM and emits a dark counterpart for every rule
   that paints a light colour — same selector, same `@media` conditions,
   colours remapped by lightness while hue is preserved and brand/status
   colours are kept. The result is attached as a constructed stylesheet
   (`document.adoptedStyleSheets`), which the cascade places after the page's
   own sheets, so it wins without `!important` and inline styles are left
   alone (app icons, chart colours, status dots keep their colours). It
   watches for new `<style>`/`<link>` nodes, rules inserted through the
   CSSOM (styled-components does this in production) and open shadow roots,
   and recompiles only the sheets that changed. The work runs synchronously
   inside the mutation callback, in the same task as the page's own change
   and therefore before the browser paints the next frame, which is what
   keeps navigation and scrolling free of light flashes. A tiny page-world
   script (`src/page-hook.js`, `world: "MAIN"`) reports direct CSSOM edits
   such as `insertRule`, which never touch the DOM, so even those are themed
   in the same task. Each source sheet
   gets its own compiled sheet, so updating a small one never rebuilds the
   big ones. Surfaces painted through
   `element.style` by JavaScript (sticky bars, animated headers) are matched
   by their literal declaration text, so they are themed too without ever
   writing to the DOM. Grey SVG glyphs coloured through `fill="#333"`-style
   presentation attributes are lightened the same way; colourful artwork is
   never touched.
   SVGs served as `<img src="….svg">` are fetched (from the browser cache),
   recoloured in the SVG *text* and re-served through a data URL, so no
   markup is parsed: both consoles enforce Trusted Types, and the end-to-end
   fixture enforces it too. The Play Console wordmark gets one exact fill
   swap; the console's artwork (dashboard "Get started" cards, empty states
   on Statistics / Releases / Reviews / Store listings) goes through an
   *illustration* mode: the white canvas becomes transparent, neutral greys
   are mapped onto dark tiers that keep their tonal order, dark ink becomes
   light, and brand accents (Google blue / green / yellow / red) are kept.
   Images stay invisible until their dark version has decoded, so the light
   original never flashes; if a fetch fails the image is shown as served.
3. **Static CSS** (`styles/`) for what neither layer can reach: the
   cross-origin One Google bar, the Play Console splash screen, the Apple
   logo mask, scrollbars and selection colours.

Turning the theme off reverses all three layers instantly; no reload needed.

### Known limitations

- Cross-origin iframes (Google's survey prompt, the Google account menu)
  render their own light UI and cannot be themed by a content script.
- Photos and screenshots are intentionally left untouched; only the consoles'
  own vector artwork is recoloured.

## Testing

```bash
node scripts/e2e/run.mjs
```

Loads the unpacked extension into headless Chromium through the DevTools
protocol (Chrome 137+ ignores `--load-extension`), serves a fixture over
local HTTPS that impersonates `play.google.com/console`, and asserts that
inline, external, `@media`, runtime-inserted and shadow-root rules are
remapped, that inline styles and accent colours survive, and that toggling
the extension off through its own service worker restores the page. It then
opens the popup as an extension page, checks it (brand icons, status text,
row toggles persist, no errors) and saves `scripts/e2e/out/popup.png`.
The runner looks for a Playwright-cached Chromium / Chrome for Testing
binary; pass another binary as the first argument if needed.
